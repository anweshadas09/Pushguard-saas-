PRE-PUSH VERIFICATION & REPAIR

Catch it before you push.

PushGuard checks your code locally, explains what failed, fixes it only with your approval, and pushes only when the checks pass.

$ pushguard push

Concept CLI. The demo below is simulated; no real Git command runs.

01 / THE FLOW

Detect. Explain. Fix with consent. Verify.

DETECTLint, typecheck, tests, build, custom checks.
EXPLAINFile, line, likely cause. Push not started.
PROPOSESmallest patch from a local model, shown as a diff.
VERIFYSnapshot, apply, re-run the whole pipeline.
PUSHOnly after the gate passes and you confirm.

02 / THE RULES

 
The pipeline is the authority.

 

  
The model never decides.
   
  • No automatic edits and no push without your yes.
  • Every patch is shown as a diff first.
  • A snapshot is taken before any change, so rollback is always possible.
  • A repair limit (default 5) prevents endless loops.
  • The model runs locally (Ollama) and never sees secrets or .env values.

  
Only code failures go to repair.
   
CODElint, types, tests, build. Repairable.
GITremote, auth, oversized objects.
RESOURCELFS or CI quota. Warn only.
ENVIRONMENTmissing runtime or variable.
NETWORKremote unreachable.
CONFIG / UNKNOWNreported, never auto-fixed.

 






 
03 / CONFIG

 
One file, any language.

 
version: 1
checks:
  - name: lint
    command: npm run lint
  - name: test
    command: npm test
ai:
  enabled: true
  provider: ollama
repair:
  require_approval: true
  max_attempts: 5
git:
  confirm_before_push: true
